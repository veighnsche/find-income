## Target and current-code baseline

The owner's [current product definition](product-vision.md) sets **seven owner-visible steps**: **Your goals → Find jobs → Select jobs → Check job details → Answer questions → Prepare materials → Handoff**. “Handoff” is a working label for the separate final saved-artifacts/how-to-apply page, **not** the prototype's Review & send stage. The app never fills or autofills an employer-site form, attaches files there, emails, submits a portal or contacts an employer. The owner personally opens the site, enters form values, attaches files or sends email. The [acceptance document](connected-prototype-ux-acceptance.md) makes the screen/state result checkable. The owner's [prototype screenshot](assets/connected-prototype-first-use-2026-09-25.png) anchors the opening layout and information hierarchy; its seventh chip changes meaning. Match UI structure, controls, navigation and usability, **not** colors, fonts, borders, rounded corners, shadows or pixel spacing.

This is a delta plan for the existing `apps/vite-app` and API, not a new architecture. Reuse functioning saved briefs, Jev assessments, selection, Check records, answer boxes, preparation/versioning and artifact export after verifying them. Scripted prototype jobs, fixture browser passes and code presence do not prove live Contributor research or Standard drafting. The older [difference audit](prototype-ui-ux-differences.md) remains useful for observed screen gaps but its **six-stage/always-three-artifact scope is superseded** by the product definition and this plan.

## Rules for all lanes

- Step 1 uses ordinary deterministic controls for explicit **wants and don't-wants**. Show sourced past experience separately so history never silently becomes future preference. Existing known facts may prefill context; the owner can enter and change their own search choices.
- This newer owner instruction supersedes older documents where they require a conversational goals form or employer contact behind review/send. Preserve their useful source-grounding and exact-edit safeguards within the seven-step manual workflow.
- The Contributor CLI chooses public sources, boards, career pages, APIs and queries freely. Jev classifies the collected listings using the owner's brief and saved reason catalog; Unknown is reserved for a genuine lack of basis, not a missing field in an otherwise usable listing.
- Initial discovery/classification never triggers a deep dive. Only jobs the owner selected and started through Check chosen jobs receive Contributor vacancy/route research. Label **actual employer questions** with source evidence. If Muse asks the owner for an unknown personal fact derived from a requirement, label that as an **owner clarification**, not an invented employer question.
- Answer questions uses Jev and deterministic known-fact copying, **no Contributor/Standard/LLM call**. The owner can edit, replace, clear or add relevant answer text. New owner text is not silently promoted to an approved reusable-answer library.
- Standard drafts only materials justified by the verified route and requirements. Each produced artifact/form value is fully readable, directly editable, versioned and usable outside the app. Direct exact edits make no model call; a separate explicit rewrite uses Standard and creates a new inspectable version.
- The separate Handoff page saves the job and current artifacts, explains verified manual email/website steps and never claims the owner applied merely because a link was opened or a file copied. Form values are saved, editable, **copyable text**, not instructions for an agent or browser to fill an employer site. No app control or callable product route fills/autofills a form, attaches files on an employer site, sends or submits anything.
- Opening, refreshing, changing tabs, reading evidence or returning to saved work starts no new search, check, draft or external action. No backward-compatibility layer is needed for this unused, undeployed app.
