# Codex native tool boundary

Use the pinned Codex supported named permission profile: deny root/private state, allow only minimal runtime and read-only work paths, and disable native networking. Disable supported shell, browser, search, image, app, plugin, delegation and goal capabilities; never approve native escalation. Remove legacy thread/turn sandbox overrides so default_permissions actually applies. Recruitment actions use the guarded jobseek MCP bridge.

The pinned binary still advertises apply_patch and request_user_input. The acceptance property is enforced denial of private-state reads, native writes and networking; it is not an MCP-only tool list. Native input requests cannot approve actions or create a chat. Trusted App Server lifecycle, authentication and model transport operate outside the native-tool sandbox.

The synthetic Linux probe proved targeted native handler denials and a successful writable positive control. Three independently worded Jev consultations advised this implementation direction, with substantial confidence variation; see [requests, responses and review](/Users/vince/Projects/find-income/implementation-notes/implementation/I13-native-consultation/review.md). Actual runner wrapper, ChatGPT account, required MCP, effective-profile, private-sentinel, Stop and idle checks remain mandatory before live acceptance. No deployment has been completed.
