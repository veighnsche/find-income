## Starting point and fixed boundaries

The saved-brief correction and discovery controls, role selection, check/answer interactions, material/review guards and browser fixtures already have implementation evidence (RW-A1/A2/B1/C1/C2/A3/B2/A4/C3/E2/E3/E4). Reuse them. Current `codexservice` research tools include `context_read` with owner facts; current material drafting uses a Codex one-shot; neither is a Muse integration. RW-D1, RW-D2, RW-D3 and live gates RW-G1–G5 remain open. The owner chose this MacBook and its installed Muse Code 1.3.0 CLI; subscription credential lane, Standard entitlement, local retrieval containment, isolated test mail and live behavior remain unverified.

Contributor through the installed CLI freely chooses and adapts public sources, queries, APIs and company career pages, captures public vacancies and, only for owner-selected roles after **Check chosen jobs**, public details and actual employer questions. General non-identifying role/region/skill criteria are allowed; owner identity, private profile/CV/answers, private Jev inputs/results and private session history are excluded from Contributor prompts, tools, logs and memory. Jev classifies with Choice/Score, selects saved reason text and owner-approved answers or `no_fitting_answer`. **Answer** reads saved actual questions and makes zero generative calls. Standard through the **same local CLI** is reserved for grounded required-answer/CV/message drafting in **Prepare applications** and explicit owner-requested rewrite. Exact owner review and explicit send remain required. Never replace adaptive discovery with a fixed source universe or canned jobs: the earlier single-source shortcut produced an irrelevant India vacancy.

M alone changes shared HTTP routes, OpenAPI, generated clients and `src/api/client.ts`. Workers request a contract change from M; they do not edit shared files in place. Assign exact files before each task. Run independent ready lanes **in parallel** after E01, using isolated worktrees/checkouts, one writer per file and no more workers than available slots. Stage dependent tasks at the graph's evidence and integration gates rather than starting every task at once. M integrates passing lane commits at E06/E08/E09, resolves any conflict, reruns checks affected by the resolution and commits the integrated result. The main Muse agent must implement E01/E02 and the integration tasks itself while coordinating bounded worker lanes.
